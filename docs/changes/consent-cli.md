# Echo 1.2 consent: CLI lane changes

Every user-visible change of the cli lane (commands, flags, output text,
defaults, exit codes, behaviour) with the exact text a user sees. The
docs team writes the wiki from this file and real command output.

## L1 consent command, subcommands and help

- New command `rhythm echo consent [<url>...] [flags]` (also `rhythm e consent`, `rhythm-echo consent`).
- Subcommands, picked by the first word that isn't a flag or a flag's value: `detect`, `report`, `verify`, `cmps`, `trackers`, `prune`. Anything else is a URL. `rhythm echo consent --json cmps` is the `cmps` subcommand.
- A subcommand's name later on the line is refused: `rhythm echo: consent "report": report is a subcommand; put it first (rhythm echo consent report), or write the host as a URL (http://report/)` (exit 2).
- `rhythm echo consent --help` (and `rhythm echo help consent`) prints the one-line pitch, the flags in the groups `What to check`, `Compare`, `Requests and browser`, `Output`, `Settings`, then `Subcommands`, `Exit codes`, three examples (`rhythm echo consent https://staging.shop.test`, `rhythm echo consent --runs +gpc --geo de https://shop.example`, `rhythm echo consent --against baseline --fail-on broke`) and the honest limits of PRD 15 (`consent.HonestLimits`) wrapped at 80 columns. Every line after the first fits 80 columns.
- Each subcommand has its own `--help` listing only the flags it reads, ending `rhythm echo consent --help lists the consent check's flags.` and `rhythm echo help lists every command.`
- Flags of the check, with defaults: `--runs <list>` (none,accept,reject), `--pages <n>` (1), `--settle <d>` (3s), `--banner-wait <d>` (10s), `--timeout <d>` (90s), `--retries <n>` (1), `--cmp <name>` (auto), `--accept-selector <sel>`, `--reject-selector <sel>`, `--click <how>` (button), `--consent-mode <policy>` (advanced), `--exempt <tracker>` (repeatable), `--geo <cc>`, `--locale <tag>`, `--timezone <tz>`, `--viewport <v>` (desktop), `--echo[=<url>]`, `--send-hits`, `--sites <file>`, `--parallel <n>` (3), `--map-host <host=addr>` (repeatable), `--map-only`; `--save <name>`, `--against <name|path|last>`, `--accept <key>` (repeatable); `-H, --header <h>` (repeatable), `--cookie <c>` (repeatable), `-A, --user-agent <ua>`, `--proxy <url>`, `-k, --insecure`, `--insecure-public`, `--follow-host`, `--browser <path>`, `--no-download`, `--no-sandbox`, `--show-browser`; `--json --md --junit --html`, `-o, --output <file>` (repeatable), `--har`, `--no-screenshots`, `--show-ids`, `--sign-key <file>`, `--open`, `-q, --quiet`, `--plain`, `--no-color`, `-v, --verbose`, `--live`, `--fail-on <level>`; `--config <file>`, `--store <dir>`.
- Subcommand flags: `verify --key <file>`, `prune --keep <n>` (default 20).
- Which subcommand reads which flag:
  - `detect`: the request and browser flags (`-H`, `--cookie`, `-A`, `--proxy`, `-k`, `--insecure-public`, `--follow-host`, `--browser`, `--no-download`, `--no-sandbox`, `--show-browser`), `--cmp`, `--accept-selector`, `--reject-selector`, `--banner-wait`, `--geo`, `--locale`, `--timezone`, `--viewport`, `--map-host`, `--map-only`, `--json`, `-q`, `--plain`, `--no-color`, `--config`, `--store`. The lane spec lists no `--timezone`, `--map-host`, `--map-only`, `--config`, `--store` or `-q`/`--plain`/`--no-color` for detect. They are added: `--timezone` shapes the browser as `--geo` and `--locale` do; the testbed reaches its sites only through `--map-host`; detect saves its screenshot in the store.
  - `report`: `--against`, `--accept`, `--json --md --junit --html`, `-o`, `--open`, `-q`, `--plain`, `--no-color`, `-v`, `--fail-on`, `--config`, `--store`.
  - `verify`: `--key`, `--json`, `-q`, `--plain`, `--no-color`.
  - `cmps`: `--json`, `-q`, `--plain`, `--no-color`. `trackers`: the same plus `--config` (custom trackers).
  - `prune`: `--keep`, `-q`, `--config`, `--store`.
- A flag a subcommand doesn't read is Echo's usage error, the flag spelled by its long name: `rhythm echo: --har has no effect on consent cmps (rhythm echo consent cmps --help lists its flags)`; two flags: `rhythm echo: --output and --runs have no effect on consent detect (rhythm echo consent detect --help lists its flags)` (exit 2).
- An unknown flag: `rhythm echo: unknown flag --rnus; did you mean --runs?` (the subcommand's own flags first, then any consent flag); `rhythm echo: --pages needs a value`; `rhythm echo: --settle "soon": want a duration like 10m or 5s`; `rhythm echo: --pages "many": want a whole number`; `rhythm echo: --echo "ftp://x": want Echo's address, e.g. --echo=http://127.0.0.1:8025` (exit 2).
- `--fail-on`: Echo's parser and words: `rhythm echo: --fail-on "high": want none, error, warning or notice (or broke, new, changed when comparing)`; with `--against`: `rhythm echo: --fail-on "warning": want none, broke, new or changed` (exit 2). Default `error`, or `broke` with `--against`.
- URL rules: only http and https; `https://` is added when there is no scheme (`shop.test` is `https://shop.test/`, `localhost:8443` is `https://localhost:8443/`); a path is read against `site:`; an empty path becomes `/`.
  - Any other scheme (file, data, javascript, chrome, devtools, view-source, about, ftp and the rest): `rhythm echo: consent "ftp://shop.test": want an http or https URL` (exit 2).
  - A login in the URL: `rhythm echo: consent "https://•••••@shop.test/": a URL with a login in it isn't allowed; pass it with -H "Authorization: env:RHYTHM_ECHO_NAME"` (masked; exit 2).
  - A path without `site:`: `rhythm echo: consent "/shop/": a path needs site: in .echo/config.yaml; give the whole URL, e.g. https://staging.shop.test/shop/` (exit 2).
  - A `site:` that isn't http or https: `rhythm echo: consent "/shop/": site: "ftp://x" isn't an http or https URL` (exit 2).
  - An empty URL: `rhythm echo: consent: an empty URL; give a page like https://staging.shop.test/` (exit 2).
- No page: `rhythm echo: consent needs a page: rhythm echo consent https://staging.shop.test, or list pages under consent: urls in .echo/config.yaml` (exit 2).
- Output: `-o` is repeatable and each file takes its format from its extension (`.json`, `.md`/`.markdown`, `.xml` for JUnit, `.html`/`.htm`). A file whose extension says nothing takes the one format flag given (`--md -o summary.txt`); otherwise `rhythm echo: can't tell the format of report.pdf; add --json, --md, --junit or --html` (exit 2). A format flag that no `-o` of that format uses writes that format to stdout; two such: `rhythm echo: pick one output format, not --json and --md` (exit 2).
- Value checks of the check's flags (exit 2): `rhythm echo: --cmp "cookiebott": want auto or one of cookiebot, onetrust, cookieyes, complianz, usercentrics, borlabs, didomi, iubenda, generic; did you mean cookiebot?`; `rhythm echo: --geo "deu": want a two-letter country code (ISO 3166-1 alpha-2), e.g. de`; `rhythm echo: --locale "german!": want a language tag like de-DE or en-US`; `rhythm echo: --timezone "Berlin time": want an IANA time zone like Europe/Berlin or UTC`; `rhythm echo: --viewport "tablet": want desktop or mobile`; `rhythm echo: --proxy "ftp://•••••@proxy.test": want http://, https:// or socks5:// and a host, e.g. socks5://127.0.0.1:1080` (the value masked: a login shows as `•••••`); `rhythm echo: --proxy "http://•••••@proxy.test:8080": the browser can't log in to a proxy from its URL; use one that needs no login, e.g. a local tunnel`; `rhythm echo: --accept-selector: selector "a >> >> b": step 2 is empty`; `rhythm echo: --reject-selector: selector is empty`; and the core texts for `--runs`, `--consent-mode`, `--click` and the ranges (`--pages 11: want 0 to 10`, `--settle 45s: want at most 30s`, `--banner-wait 2m: want at most 60s`, `--timeout 11m: want at most 10m`, `--timeout 0s: want more than 0 and at most 10m`, `--retries 5: want 0 to 3`, `--parallel 9: want 1 to 8`), each after `rhythm echo: `. `consent/cli/testdata/usage-messages.golden` holds them all.
- `--locale` and `--timezone` left unset mean the machine's own; the plan carries "" so the browser lane can let `--geo` pick them while an explicit `--locale` or `--timezone` wins.

## L2 config: consent block, validation, init --consent

- `consent:` in `.echo/config.yaml` takes the keys of PRD 8.1: `urls`, `runs`, `pages`, `settle`, `banner_wait`, `timeout`, `retries`, `cmp`, `click`, `accept_selector`, `reject_selector`, `consent_mode`, `geo`, `locale`, `timezone`, `viewport`, `parallel`, `exempt`, `headers`, `map_hosts`, `ignore`, `trackers`. An empty `consent:` is the same as none.
- Every error names its line; `rhythm echo consent` prints it as `rhythm echo: <config file>: line N: ...` (exit 2), as every config error in Echo does. The PRD 10.2 texts follow the `line N: ` part.
- An unknown key: `line 3: consent: runz isn't a key; did you mean runs?`; with nothing close: `line 3: consent: zzzzzzzzzz isn't a key; use urls, runs, pages, settle, banner_wait, timeout, retries, cmp, click, accept_selector, reject_selector, consent_mode, geo, locale, timezone, viewport, parallel, exempt, headers, map_hosts, ignore, trackers`. In an ignore entry: `line 7: consent: ignore: tracer isn't a key; did you mean tracker?`.
- Not a mapping: `line 2: consent: want keys like urls: and runs:, e.g. consent: {urls: [/]}`.
- `urls`: `line 3: consent: urls: "ftp://shop.test": want an http or https URL, or a path like /shop/`; `line 2: consent: urls: "/shop/" is a path; set site: or give the whole URL`; a login: `consent: urls: "https://•••••@shop.test/": a URL with a login in it isn't allowed; use headers: with ${env:RHYTHM_ECHO_NAME}`.
- Values in the flags' words with the config key: `line 3: consent: runs "decline": want none, accept, reject, gpc or withdraw (+gpc adds one); did you mean reject?`; `consent: pages 11: want 0 to 10`; `consent: retries 4: want 0 to 3`; `consent: parallel 9: want 1 to 8`; `consent: settle 31s: want at most 30s`; `consent: banner_wait 2m: want at most 60s`; `consent: timeout 11m: want at most 10m`; `consent: timeout 0s: want more than 0 and at most 10m`; `consent: cmp "quantcast": want auto or one of cookiebot, onetrust, cookieyes, complianz, usercentrics, borlabs, didomi, iubenda, generic`; `consent: click "mouse": want button, api or button,api`; `consent: consent_mode "loose": want advanced, basic or strict`; `consent: reject_selector: selector "#a >> ": step 2 is empty`; `consent: geo "deu": want a two-letter country code (ISO 3166-1 alpha-2), e.g. de`; `consent: locale "german!": want a language tag like de-DE or en-US`; `consent: timezone "Berlin time": want an IANA time zone like Europe/Berlin or UTC`; `consent: viewport "tablet": want desktop or mobile`; `consent: exempt: an empty tracker id; rhythm echo consent trackers lists them`.
- `headers`: a name that isn't a header name: `consent: headers: "Bad Name" isn't a header name`; a value that isn't `${env:RHYTHM_ECHO_<NAME>}` is message 7: `line 4: consent: headers: Authorization: use ${env:RHYTHM_ECHO_NAME}, not the value itself; secrets never sit in the config`. The value is never quoted back.
- `map_hosts`: `consent: map_hosts: *.shop.test: "nowhere": want host:port or an http:// URL, e.g. 127.0.0.1:18950`; `consent: map_hosts: "https://x/": want a host name or *.name, e.g. *.shop.test`.
- `ignore` entries: `consent: ignore: needs check, a consent check ID like consent/before-choice`; `consent: ignore: check consent/befor-choice isn't a consent check; did you mean consent/before-choice?`; `consent: ignore: consent/before-choice: needs a reason, e.g. reason: "client signs off until the Nov launch"`; `consent: ignore: consent/before-choice: needs until, the date it stops applying, e.g. until: 2026-11-30`; `consent: ignore: consent/before-choice: until "next week": want a date like 2026-11-30`; `consent: ignore: consent/before-choice: run "decline": want none, accept, reject, gpc or withdraw`; more than 365 days from today: `consent: ignore: until 2028-01-01 is more than a year away; review it sooner`. A date already past is accepted (the entry stops applying; the verdict adds `consent/ignore-expired`).
- `trackers` must be a list: `consent: trackers: want a list of trackers, each like the catalog's (id, name, category, hits, fixtures)`; the classifier checks the entries when consent runs.
- `checks:`: a `consent/` ID that isn't a consent check, with or without a `consent:` block: `line 2: checks: consent/befor-choice isn't a check; did you mean consent/before-choice?`, or `...isn't a check; rhythm echo checks lists them`. A consent check takes only `off`, `notice`, `warning` or `error`: `line 2: checks: consent/after-reject: "broke" isn't off, notice, warning or error`.
- New `rhythm echo init --consent [--force]`. With a config: appends a commented `consent:` block (every key with its default and a one-line comment; the file still loads) and prints `Added a consent: block to .echo/config.yaml; uncomment a key to change its default.` The block's commented `ignore:` example has `until:` set to 30 days after the day init runs. With none (or with `--force`): writes a config with only that block and prints `Wrote .echo/config.yaml with a consent: block; uncomment a key to change its default.` Both then print `Then: rhythm echo consent https://staging.shop.test (or list pages under consent: urls).` A config that already has `consent:`: `rhythm echo: .echo/config.yaml already has consent:` (exit 2). With `--stack`: `rhythm echo: --consent writes only the consent: block; leave out --stack` (exit 2). `rhythm echo init --help` gains `rhythm echo init --consent [--force]` and the `--consent` line; the top-level help's init entry gains `--consent adds a commented consent: block instead`.

## L3 Building the Plan

- Precedence: the defaults of PRD 7, then `consent:` in the config, then the flags, then for `--sites` each site's `consent.args` for that site's pages. `-H` wins over `consent: headers` for the same name. `--exempt` adds to `consent: exempt`.
- Pages: the URLs given, else `consent: urls` (read against `site:`). `--sites` with URLs as well: `rhythm echo: give pages or --sites, not both` (exit 2).
- `-H "Name: value"` and `--cookie name=value`: the value may be `@file` (read, at most 64 KiB, trimmed) or `env:NAME`; `--cookie @file` and `--cookie env:NAME` read the whole `name=value`. Errors never quote a value:
  - `rhythm echo: --header Authorization: env:RHYTHM_ECHO_STAGING_AUTH is not set`
  - `rhythm echo: --header X: @big.txt is more than 64 KiB`; `rhythm echo: --header X: @token.txt doesn't exist`
  - `rhythm echo: --header: want "Name: value", e.g. -H "Authorization: env:RHYTHM_ECHO_STAGING_AUTH"`
  - `rhythm echo: --header X: has a line break`
  - `rhythm echo: --cookie: want name=value, e.g. --cookie "session=env:RHYTHM_ECHO_SESSION"`; `rhythm echo: --cookie session: the value has a ; or a line break; give one cookie per --cookie`
  - (all exit 2)
- A plain value prints PRD 10.2 message 22 on stderr once per command: `rhythm echo: --header value on the command line shows in ps to every user on this machine; use @file or env:NAME`; for cookies `rhythm echo: --cookie value on the command line shows in ps to every user on this machine; use @file or env:NAME`.
- `consent: headers` values `${env:RHYTHM_ECHO_NAME}` are read from the environment: unset is `rhythm echo: consent: headers: Authorization: RHYTHM_ECHO_STAGING_AUTH is not set` (exit 2).
- `--send-hits` on a host under `production:` (the host or a subdomain, as Echo's actions match) is message 6 before any browser starts or any folder is made: `rhythm echo: --send-hits on www.shop.example.com, which matches "shop.example.com" under production:. Echo holds tracker hits on production so your analytics stay clean; leave --send-hits off` (exit 2).
- `--show-ids` with `--md`, `--junit`, `-o *.md` or `-o *.xml`: `rhythm echo: --show-ids keeps tracking IDs unmasked; it can't be used with Markdown or JUnit output, which are meant to be shared` (exit 2).
- `-k` on a public site without `--insecure-public`: `rhythm echo: -k on https://shop.example/, a public site: evidence from an unverified connection proves little; add --insecure-public if you mean it` (exit 2). Private: loopback, private and link-local addresses; `localhost`; one-label names; names under `.localhost .test .local .internal .lan .home.arpa .localdomain .intranet .corp .private`; and hosts `--map-host` answers from such an address. No DNS lookup is made to decide.
- `--show-browser` sets `--parallel 1`.
- The store: `--store`, else the config's folder, else `./.echo`. Nothing is created until the check starts.
- `checks:` levels of `consent/` IDs go to the verdict (`off` removes a check). `consent: ignore` entries go to the verdict as written.
- `consent: trackers` go to the tracker catalog's `AddCustom` once per command; its error is `rhythm echo: consent: trackers: <the catalog's message>` (exit 2).
- `--map-host host=addr` (repeatable, on top of `consent: map_hosts`, the flag winning for the same host): `rhythm echo: --map-host "x": want host=address, e.g. *.shop.test=127.0.0.1:18950` (exit 2). The address is host:port or an http:// or https:// URL.
- `--echo` asks Echo at `--echo=<url>`, else `RHYTHM_ECHO_URL`, else `http://127.0.0.1:8025`, with `RHYTHM_ECHO_TOKEN`.
- `--sites <file>`: Soundcheck fleet's file, a list or a mapping with `sites:`. Per entry Echo reads `name`, `url` and `consent: {urls, args}`; Soundcheck's `config`, `env_prefix` and `args` are accepted and left alone. A site's pages default to its `url`; `consent: urls` paths are read against it. Errors (exit 2, `rhythm echo: sites.yaml: ...`):
  - `no sites listed`; `line 1: "sitez" isn't a key; did you mean sites?`; `line 1: a site: "envprefix" isn't a key; did you mean env_prefix?`; `line 1: consent: "url" isn't a key; did you mean urls?`
  - Soundcheck's name rules: `site "../acme": name must be letters, digits, dots, dashes and underscores (up to 64), starting with a letter or digit`; `site "Acme": the name is already used by site "acme"` (compared without case); `site "acme": url is missing`; `site "acme": url "ftp://a.test": want an http or https URL`.
  - A site's `consent.args` may set only `--runs --pages --settle --banner-wait --timeout --retries --cmp --accept-selector --reject-selector --click --consent-mode --exempt --geo --locale --timezone --viewport --follow-host -A -H --cookie`; anything else: `site "a": consent: args can't set --send-hits; only the command line can`. `-H` and `--cookie` values there must be `env:RHYTHM_ECHO_NAME` and not one of Echo's own variables (`RHYTHM_ECHO_TOKEN`, `RHYTHM_ECHO_WRITE_TOKEN`, `RHYTHM_ECHO_URL`, `RHYTHM_ECHO_SMTP`, `RHYTHM_ECHO_RELAY`, `RHYTHM_ECHO_LOGIN`, `RHYTHM_ECHO_PROXY`, `RHYTHM_ECHO_RUN`): `site "a": consent: args: header and cookie values must be env:RHYTHM_ECHO_NAME, never a file, the value itself or one of Echo's own variables (RHYTHM_ECHO_TOKEN, RHYTHM_ECHO_URL and the like)`. A page in args: `site "a": consent: args take flags only, not "/menu/"; list pages under consent: urls`. The file is shared, so nothing in it can read files, run programs, send hits, unmask IDs, turn off TLS checks or move results.
  - A sites file over 4 MiB: `--sites sites.yaml: the file is more than 4 MiB`.
- More than 50 pages in one check: `rhythm echo: 63 pages is more than 50 for one check; split the sites file` (exit 2).

## L4 Running a check and printing it

- Before anything runs: the config, the plan, `--against` (loaded now) and `--save`'s name are checked; every stage the check needs must be linked, else `rhythm echo: consent: tracker, signal, state reader, cmp, browse, verdict not linked into this build` (only the missing ones; exit 3). Nothing is created until all of that passes.
- A check that stops on a fatal error (exit 3) removes its result folder, also when an earlier `--sites` site had finished: no folder is left without a `consent.json`.
- The once-only notice (kit `FirstRun` key `echo-consent-notice`; never in CI, with `-q` or with `--json` on stdout), on stderr before the run:
  ```
  Note: use Echo on sites you own or are authorised to test. Consent checks load the site like
  one new visitor: they never log in or submit forms and every tracking hit is recorded and
  stopped in the browser. Results stay on this machine with IDs masked. This notice is shown once.
  ```
- Run warnings on stderr, once per command: `rhythm echo: Chrome is running without its sandbox (--no-sandbox); only check sites you trust` (with `--no-sandbox`, `RHYTHM_ECHO_NO_SANDBOX=1` or `SOUNDCHECK_NO_SANDBOX=1`) and PRD 10.2 message 23 `rhythm echo: --send-hits: this run sends real tracking hits to Google, Meta and the other trackers on the page`. The plain-value warnings of L3 print here too.
- The browser layer's Chrome download line goes to stderr (`Plan.Browser.Log`).
- The result folder is `<store>/consent/<YYYY-MM-DDTHH-MM-SS>-<6 hex>` (0700); the store is added to `.git/info/exclude` as Echo's other results are.
- Output order: `--against` comparison, then `consent.json` (0600; it lists the SHA-256 of every file under `events/`, `evidence/` and `har/`), then `report.html` always, `report.md` with `--md`, `-o *.md` or in GitHub Actions (`GITHUB_ACTIONS=true`), `report.xml` with `--junit` or `-o *.xml`, each stating `consent.json`'s hash, then `manifest.json` (schema `rhythm-echo-consent-manifest/v1`, `{path, bytes, sha256}` of every other file, sorted), then the `-o` files and the format on stdout, then the terminal view, then `--save`, then one tip. `data.evidence.folder` is the folder relative to the working folder, with forward slashes.
- `--json` (or any one format flag without its `-o`) puts that format alone on stdout; the terminal view then goes to stderr. Otherwise the view is on stdout.
- `-o` files are written atomically, 0600, their folders made 0700.
- `--live` prints one line per tracker hit on stderr as the browser records it: `hit  0.84s  before the choice  Meta Pixel  www.facebook.com/tr (held)`; after the choice the run's name stands in that place (`Accept`, `Reject`, `GPC`, `Withdraw`). Script loads, cookies and storage aren't hits and print nothing. Page text passes `consent.SafeText`.
- `--open` opens `report.html` with the opener Echo's other commands use.
- Tips, at most one per command, each once per machine (kit `FirstRun` keys `echo-consent-tip-reject`, `-geo`, `-save`, `-gpc`), never in CI, with `-q` or with `--json`, in this order of preference: a run that found no Reject or Accept button: `Tip: rhythm echo consent detect <url> shows the buttons Echo sees.`; a run with no banner or the `consent/no-banner` issue: `Tip: banners that show only in some countries need --geo or an EU --proxy.`; a complete check at exit 0 without `--save` or `--against`: `Tip: --save baseline keeps this as the baseline for the next check.`; advertising trackers and no gpc run: `Tip: --runs +gpc also checks Global Privacy Control.`
- A check that stopped (exit 3; its empty result folder is removed): PRD 10.2 messages 9 to 16 after `rhythm echo: `, with masked URLs:
  - `no Chrome or Chromium found; install Chrome, pass --browser /path/to/chrome, or allow the one-time Chrome for Testing download`; with `RHYTHM_ECHO_IMAGE=1` it is message 16 instead.
  - `Chrome won't start without its sandbox as root; run as another user, or pass --no-sandbox (only for sites you trust)`
  - `https://staging.shop.test/ didn't answer: dial tcp 127.0.0.1:443: connection refused. Is the site running? A local site with a self-signed certificate needs -k`
  - `https://staging.shop.test/ answered 401 Unauthorized; pass the login with -H "Authorization: env:RHYTHM_ECHO_STAGING_AUTH" or consent: headers:` (also for 407); any other status: `https://staging.shop.test/ answered 503 Service Unavailable; check that the site serves its pages, then run the check again`
  - `https://shop.example.com/ showed a bot check (Cloudflare) instead of the page; allow this machine in the firewall for the check, or check staging` (without a vendor: `showed a bot check instead of the page; ...`)
  - `https://shop.test/ redirects to https://shop.example.com/; check that one, or pass --follow-host`
  - `https://shop.example/ uses a certificate this machine doesn't trust (x509: certificate signed by unknown authority); pass -k for a local or private site`
  - `this image has no browser; run rhythm echo consent on the host, or pass --browser`
  - a redirect loop: `https://shop.test/ redirects in a loop or through more than 10 hops; check the site's redirects`
  - the runner's write error: `couldn't write <file>: <error>`
- A report that can't be written: `rhythm echo: couldn't write .echo/consent/<id>/report.html: <error>` (or the `-o` path; exit 3).
- Exit codes: the result's own (`consent.Result.ExitCode` for `--fail-on`): 0, 1 (wins over 3), 3; `--fail-on none` with an error is 0, with an inconclusive run still 3. Ctrl-C or SIGTERM: the finished runs are judged and written (`complete: false` in the JSON report; `consent.json` gets the note `Interrupted before every run finished: this result is incomplete.`), then `rhythm echo: interrupted; the runs that finished are kept in .echo/consent/<id>` and exit 130.
- The update prompt runs through the same kit `PromptAtExit` Echo's other commands use, only on a terminal; never under `--json`, `-q`, CI or a pipe or after an interrupt.
- `--save <name>` copies `consent.json` to `<store>/consent/baselines/<name>/consent.json` after the reports: `Saved baseline baseline.`, or for an existing one `Saved baseline baseline (replaced the one from 2026-10-19 08:02).` (the old baseline's start, UTC). A name that can't be a folder: `rhythm echo: --save: "a b" isn't a valid name: use up to 64 letters, digits, dots, dashes and underscores, starting with a letter or digit` (exit 2, before the run). An incomplete check isn't saved: `rhythm echo: --save partial: not saved: a baseline needs a complete check and some runs couldn't be checked` (stderr; the exit code is the result's).
- `--against <name|path|last>` is loaded before the run: `last` is the newest result folder in `<store>/consent` (never `baselines/` or `detect/`); an existing path is a `consent.json` or a result folder; otherwise a baseline's name. Errors (exit 2, no browser started): message 5 `rhythm echo: --against "baseline": no saved consent result by that name in .echo/consent/baselines; rhythm echo consent <url> --save baseline makes one`; `rhythm echo: --against last: no consent result in .echo/consent yet; run rhythm echo consent <url> first`; `rhythm echo: --against empty: no consent.json in that folder`; `rhythm echo: --against bad.json: bad.json isn't a consent result: <error>`. The comparison's `against` is the word given.
- `--sites` plans (one per site with its own args) run one after another and make one result: every page, issue and inconclusive run, the network counts added.

## L5 Evidence pack: hashes, manifest, signing and verify

- `--sign-key <file>` signs `consent.json`: the key is checked before any browser starts and read again to sign. It must be a PEM `PRIVATE KEY` (PKCS#8 ed25519, what `openssl genpkey -algorithm ed25519 -out team.key` writes) of mode 0600 or stricter on Unix (Windows: no mode check). Refusals (exit 2, nothing written):
  - `rhythm echo: --sign-key team.key is readable by others; chmod 600 it`
  - `rhythm echo: --sign-key: want an ed25519 private key in PEM (openssl genpkey -algorithm ed25519 -out team.key)`
  - `rhythm echo: --sign-key team.key: no such file or directory` (any read error after the name)
- A signed check writes `consent.json.sig` (0600) next to `consent.json`, before the reports and the manifest, so `manifest.json` lists it: `{"algorithm": "ed25519", "key_id": "<16 hex>", "signature": "<base64>"}`. `key_id` is the first 16 hex digits of the SHA-256 of the public key's PKIX DER form (`openssl pkey -in team.key -pubout -outform DER | sha256sum`); the signature is over the exact bytes of `consent.json`.
- `WriteResult` makes the result folder (0700) when it is missing.
- New: `rhythm echo consent verify <folder|file> [--key <file>] [--json]`. A file (such as the folder's `consent.json`) stands for its folder. It recomputes the SHA-256 of every file `manifest.json` lists, checks `consent.json` is among them (one left out of the manifest is reported as not matching), checks the hashes `consent.json` lists for its attachments (so a manifest rewritten to match a changed screenshot still fails) and checks `consent.json.sig`:
  - with `--key <file>` (PEM `PUBLIC KEY`, ed25519, `openssl pkey -in team.key -pubout -out team.pub`): the signature must check; a missing one fails too. A wrong key file: `rhythm echo: --key: want an ed25519 public key in PEM (openssl pkey -in team.key -pubout -out team.pub)` (exit 2).
  - without `--key`: a signature is reported as present and not checked (`signature.key` is `""`); it doesn't fail.
- The lines and the `--json` envelope (kind `consent-verify`) come from `report.WriteConsentVerify` (verdict lane). The data's `folder` is the folder relative to the working folder, with forward slashes; a file's `got` is `""` when it is missing or unreadable.
- When `consent.json.sigstore.json` is in the folder (the Action's keyless signature), verify adds (stdout; stderr with `--json`; not with `-q`): `Sigstore bundle present: check it with cosign verify-blob --bundle consent.json.sigstore.json --certificate-identity-regexp '^https://github.com/<owner>/<repo>/' --certificate-oidc-issuer https://token.actions.githubusercontent.com consent.json`. The binary doesn't verify keyless bundles.
- Exit codes of verify: 0 every file and (with `--key`) the signature match; 1 a hash differs, or with `--key` the signature doesn't check or is missing (1 wins over 3); 3 a file is missing or unreadable, or the folder can't be checked; 2 usage.
- Messages of verify (exit 3 unless noted): `rhythm echo: consent verify empty: no manifest.json; is it a consent result folder?`; `rhythm echo: consent verify <dir>: manifest.json isn't a consent manifest (rhythm-echo-consent-manifest/v1)`; `rhythm echo: consent verify <dir>: manifest.json lists "../x", which is outside the folder`; `rhythm echo: consent verify gone: no such file or directory`; `rhythm echo: consent verify needs one evidence folder: rhythm echo consent verify .echo/consent/<id> [--key team.pub]` (exit 2). Links in the folder are never followed (a link reads as missing), nor are linked folders: a listed file whose folder resolves outside the evidence folder reads as missing.
- verify names every file in the folder that neither `manifest.json` nor `consent.json` lists (links included), one line each, `not in the manifest  <path>` (stdout; stderr with `--json`; also with `-q`); it doesn't change the exit code. With `--key` and a good signature it adds (not with `-q`): `The signature covers consent.json and the files it lists; report.html, report.md and manifest.json are checked against manifest.json only.`

# Echo 1.2 consent: CLI lane changes

Every user-visible change of the cli lane (commands, flags, output text,
defaults, exit codes, behaviour) with the exact text a user sees. The
docs team writes the wiki from this file and real command output.

## L1 consent command, subcommands and help

- New command `rhythm echo consent [<url>...] [flags]` (also `rhythm e consent`, `rhythm-echo consent`).
- Subcommands, picked by the first word that isn't a flag or a flag's value: `detect`, `report`, `verify`, `cmps`, `trackers`, `prune`. Anything else is a URL. `rhythm echo consent --json cmps` is the `cmps` subcommand.
- A subcommand's name later on the line is refused: `rhythm echo: consent "report": report is a subcommand; put it first (rhythm echo consent report), or write the host as a URL (http://report/)` (exit 2).
- `rhythm echo consent --help` (and `rhythm echo help consent`) prints the one-line pitch, the flags in the groups `What to check`, `Compare`, `Requests and browser`, `Output`, `Settings`, then `Subcommands`, `Exit codes`, three examples (`rhythm echo consent https://staging.shop.test`, `rhythm echo consent --runs +gpc --geo de https://shop.example`, `rhythm echo consent --against baseline --fail-on broke`) and the honest limits of PRD 15 (`consent.HonestLimits`) wrapped at 80 columns. Every line after the first fits 80 columns.
- Each subcommand has its own `--help` listing only the flags it reads, ending `rhythm echo consent --help lists the consent check's flags.` and `rhythm echo help lists every command.`
- Flags of the check, with defaults: `--runs <list>` (none,accept,reject), `--pages <n>` (1), `--settle <d>` (3s), `--banner-wait <d>` (10s), `--timeout <d>` (90s), `--retries <n>` (1), `--cmp <name>` (auto), `--accept-selector <sel>`, `--reject-selector <sel>`, `--click <how>` (button), `--consent-mode <policy>` (advanced), `--exempt <tracker>` (repeatable), `--geo <cc>`, `--locale <tag>`, `--timezone <tz>`, `--viewport <v>` (desktop), `--echo[=<url>]`, `--send-hits`, `--sites <file>`, `--parallel <n>` (3), `--map-host <host=addr>` (repeatable), `--map-only`; `--save <name>`, `--against <name|path|last>`, `--accept <key>` (repeatable); `-H, --header <h>` (repeatable), `--cookie <c>` (repeatable), `-A, --user-agent <ua>`, `--proxy <url>`, `-k, --insecure`, `--insecure-public`, `--follow-host`, `--browser <path>`, `--no-download`, `--no-sandbox`, `--show-browser`; `--json --md --junit --html`, `-o, --output <file>` (repeatable), `--har`, `--no-screenshots`, `--show-ids`, `--sign-key <file>`, `--open`, `-q, --quiet`, `--plain`, `--no-color`, `-v, --verbose`, `--live`, `--fail-on <level>`; `--config <file>`, `--store <dir>`.
- Subcommand flags: `verify --key <file>`, `prune --keep <n>` (default 20).
- Which subcommand reads which flag:
  - `detect`: the request and browser flags (`-H`, `--cookie`, `-A`, `--proxy`, `-k`, `--insecure-public`, `--follow-host`, `--browser`, `--no-download`, `--no-sandbox`, `--show-browser`), `--cmp`, `--accept-selector`, `--reject-selector`, `--banner-wait`, `--geo`, `--locale`, `--timezone`, `--viewport`, `--map-host`, `--map-only`, `--json`, `-q`, `--plain`, `--no-color`, `--config`, `--store`. The lane spec lists no `--timezone`, `--map-host`, `--map-only`, `--config`, `--store` or `-q`/`--plain`/`--no-color` for detect. They are added: `--timezone` shapes the browser as `--geo` and `--locale` do; the testbed reaches its sites only through `--map-host`; detect saves its screenshot in the store.
  - `report`: `--against`, `--accept`, `--json --md --junit --html`, `-o`, `--open`, `-q`, `--plain`, `--no-color`, `-v`, `--fail-on`, `--config`, `--store`.
  - `verify`: `--key`, `--json`, `-q`, `--plain`, `--no-color`.
  - `cmps`: `--json`, `-q`, `--plain`, `--no-color`. `trackers`: the same plus `--config` (custom trackers).
  - `prune`: `--keep`, `-q`, `--config`, `--store`.
- A flag a subcommand doesn't read is Echo's usage error, the flag spelled by its long name: `rhythm echo: --har has no effect on consent cmps (rhythm echo consent cmps --help lists its flags)`; two flags: `rhythm echo: --output and --runs have no effect on consent detect (rhythm echo consent detect --help lists its flags)` (exit 2).
- An unknown flag: `rhythm echo: unknown flag --rnus; did you mean --runs?` (the subcommand's own flags first, then any consent flag); `rhythm echo: --pages needs a value`; `rhythm echo: --settle "soon": want a duration like 10m or 5s`; `rhythm echo: --pages "many": want a whole number`; `rhythm echo: --echo "ftp://x": want Echo's address, e.g. --echo=http://127.0.0.1:8025` (exit 2).
- `--fail-on`: Echo's parser and words: `rhythm echo: --fail-on "high": want none, error, warning or notice (or broke, new, changed when comparing)`; with `--against`: `rhythm echo: --fail-on "warning": want none, broke, new or changed` (exit 2). Default `error`, or `broke` with `--against`.
- URL rules: only http and https; `https://` is added when there is no scheme (`shop.test` is `https://shop.test/`, `localhost:8443` is `https://localhost:8443/`); a path is read against `site:`; an empty path becomes `/`.
  - Any other scheme (file, data, javascript, chrome, devtools, view-source, about, ftp and the rest): `rhythm echo: consent "ftp://shop.test": want an http or https URL` (exit 2).
  - A login in the URL: `rhythm echo: consent "https://•••••@shop.test/": a URL with a login in it isn't allowed; pass it with -H "Authorization: env:RHYTHM_ECHO_NAME"` (masked; exit 2).
  - A path without `site:`: `rhythm echo: consent "/shop/": a path needs site: in .echo/config.yaml; give the whole URL, e.g. https://staging.shop.test/shop/` (exit 2).
  - A `site:` that isn't http or https: `rhythm echo: consent "/shop/": site: "ftp://x" isn't an http or https URL` (exit 2).
  - An empty URL: `rhythm echo: consent: an empty URL; give a page like https://staging.shop.test/` (exit 2).
- No page: `rhythm echo: consent needs a page: rhythm echo consent https://staging.shop.test, or list pages under consent: urls in .echo/config.yaml` (exit 2).
- Output: `-o` is repeatable and each file takes its format from its extension (`.json`, `.md`/`.markdown`, `.xml` for JUnit, `.html`/`.htm`). A file whose extension says nothing takes the one format flag given (`--md -o summary.txt`); otherwise `rhythm echo: can't tell the format of report.pdf; add --json, --md, --junit or --html` (exit 2). A format flag that no `-o` of that format uses writes that format to stdout; two such: `rhythm echo: pick one output format, not --json and --md` (exit 2).
- Value checks of the check's flags (exit 2): `rhythm echo: --cmp "cookiebott": want auto or one of cookiebot, onetrust, cookieyes, complianz, usercentrics, borlabs, didomi, iubenda, generic; did you mean cookiebot?`; `rhythm echo: --geo "deu": want a two-letter country code (ISO 3166-1 alpha-2), e.g. de`; `rhythm echo: --locale "german!": want a language tag like de-DE or en-US`; `rhythm echo: --timezone "Berlin time": want an IANA time zone like Europe/Berlin or UTC`; `rhythm echo: --viewport "tablet": want desktop or mobile`; `rhythm echo: --accept-selector: selector "a >> >> b": step 2 is empty`; `rhythm echo: --reject-selector: selector is empty`; and the core texts for `--runs`, `--consent-mode`, `--click` and the ranges (`--pages 11: want 0 to 10`, `--settle 45s: want at most 30s`, `--banner-wait 2m: want at most 60s`, `--timeout 11m: want at most 10m`, `--timeout 0s: want more than 0 and at most 10m`, `--retries 5: want 0 to 3`, `--parallel 9: want 1 to 8`), each after `rhythm echo: `. `consent/cli/testdata/usage-messages.golden` holds them all.
- `--locale` and `--timezone` left unset mean the machine's own; the plan carries "" so the browser lane can let `--geo` pick them while an explicit `--locale` or `--timezone` wins.

## L2 config: consent block, validation, init --consent

- `consent:` in `.echo/config.yaml` takes the keys of PRD 8.1: `urls`, `runs`, `pages`, `settle`, `banner_wait`, `timeout`, `retries`, `cmp`, `click`, `accept_selector`, `reject_selector`, `consent_mode`, `geo`, `locale`, `timezone`, `viewport`, `parallel`, `exempt`, `headers`, `map_hosts`, `ignore`, `trackers`. An empty `consent:` is the same as none.
- Every error names its line; `rhythm echo consent` prints it as `rhythm echo: <config file>: line N: ...` (exit 2), as every config error in Echo does. The PRD 10.2 texts follow the `line N: ` part.
- An unknown key: `line 3: consent: runz isn't a key; did you mean runs?`; with nothing close: `line 3: consent: zzzzzzzzzz isn't a key; use urls, runs, pages, settle, banner_wait, timeout, retries, cmp, click, accept_selector, reject_selector, consent_mode, geo, locale, timezone, viewport, parallel, exempt, headers, map_hosts, ignore, trackers`. In an ignore entry: `line 7: consent: ignore: tracer isn't a key; did you mean tracker?`.
- Not a mapping: `line 2: consent: want keys like urls: and runs:, e.g. consent: {urls: [/]}`.
- `urls`: `line 3: consent: urls: "ftp://shop.test": want an http or https URL, or a path like /shop/`; `line 2: consent: urls: "/shop/" is a path; set site: or give the whole URL`; a login: `consent: urls: "https://•••••@shop.test/": a URL with a login in it isn't allowed; use headers: with ${env:RHYTHM_ECHO_NAME}`.
- Values in the flags' words with the config key: `line 3: consent: runs "decline": want none, accept, reject, gpc or withdraw (+gpc adds one); did you mean reject?`; `consent: pages 11: want 0 to 10`; `consent: retries 4: want 0 to 3`; `consent: parallel 9: want 1 to 8`; `consent: settle 31s: want at most 30s`; `consent: banner_wait 2m: want at most 60s`; `consent: timeout 11m: want at most 10m`; `consent: timeout 0s: want more than 0 and at most 10m`; `consent: cmp "quantcast": want auto or one of cookiebot, onetrust, cookieyes, complianz, usercentrics, borlabs, didomi, iubenda, generic`; `consent: click "mouse": want button, api or button,api`; `consent: consent_mode "loose": want advanced, basic or strict`; `consent: reject_selector: selector "#a >> ": step 2 is empty`; `consent: geo "deu": want a two-letter country code (ISO 3166-1 alpha-2), e.g. de`; `consent: locale "german!": want a language tag like de-DE or en-US`; `consent: timezone "Berlin time": want an IANA time zone like Europe/Berlin or UTC`; `consent: viewport "tablet": want desktop or mobile`; `consent: exempt: an empty tracker id; rhythm echo consent trackers lists them`.
- `headers`: a name that isn't a header name: `consent: headers: "Bad Name" isn't a header name`; a value that isn't `${env:RHYTHM_ECHO_<NAME>}` is message 7: `line 4: consent: headers: Authorization: use ${env:RHYTHM_ECHO_NAME}, not the value itself; secrets never sit in the config`. The value is never quoted back.
- `map_hosts`: `consent: map_hosts: *.shop.test: "nowhere": want host:port or an http:// URL, e.g. 127.0.0.1:18950`; `consent: map_hosts: "https://x/": want a host name or *.name, e.g. *.shop.test`.
- `ignore` entries: `consent: ignore: needs check, a consent check ID like consent/before-choice`; `consent: ignore: check consent/befor-choice isn't a consent check; did you mean consent/before-choice?`; `consent: ignore: consent/before-choice: needs a reason, e.g. reason: "client signs off until the Nov launch"`; `consent: ignore: consent/before-choice: needs until, the date it stops applying, e.g. until: 2026-11-30`; `consent: ignore: consent/before-choice: until "next week": want a date like 2026-11-30`; `consent: ignore: consent/before-choice: run "decline": want none, accept, reject, gpc or withdraw`; more than 365 days from today: `consent: ignore: until 2028-01-01 is more than a year away; review it sooner`. A date already past is accepted (the entry stops applying; the verdict adds `consent/ignore-expired`).
- `trackers` must be a list: `consent: trackers: want a list of trackers, each like the catalog's (id, name, category, hits, fixtures)`; the classifier checks the entries when consent runs.
- `checks:`: a `consent/` ID that isn't a consent check, with or without a `consent:` block: `line 2: checks: consent/befor-choice isn't a check; did you mean consent/before-choice?`, or `...isn't a check; rhythm echo checks lists them`. A consent check takes only `off`, `notice`, `warning` or `error`: `line 2: checks: consent/after-reject: "broke" isn't off, notice, warning or error`.
- New `rhythm echo init --consent [--force]`. With a config: appends a commented `consent:` block (every key with its default and a one-line comment; the file still loads) and prints `Added a consent: block to .echo/config.yaml; uncomment a key to change its default.` With none (or with `--force`): writes a config with only that block and prints `Wrote .echo/config.yaml with a consent: block; uncomment a key to change its default.` Both then print `Then: rhythm echo consent https://staging.shop.test (or list pages under consent: urls).` A config that already has `consent:`: `rhythm echo: .echo/config.yaml already has consent:` (exit 2). With `--stack`: `rhythm echo: --consent writes only the consent: block; leave out --stack` (exit 2). `rhythm echo init --help` gains `rhythm echo init --consent [--force]` and the `--consent` line; the top-level help's init entry gains `--consent adds a commented consent: block instead`.

## L3 Building the Plan

- Precedence: the defaults of PRD 7, then `consent:` in the config, then the flags, then for `--sites` each site's `consent.args` for that site's pages. `-H` wins over `consent: headers` for the same name. `--exempt` adds to `consent: exempt`.
- Pages: the URLs given, else `consent: urls` (read against `site:`). `--sites` with URLs as well: `rhythm echo: give pages or --sites, not both` (exit 2).
- `-H "Name: value"` and `--cookie name=value`: the value may be `@file` (read, at most 64 KiB, trimmed) or `env:NAME`; `--cookie @file` and `--cookie env:NAME` read the whole `name=value`. Errors never quote a value:
  - `rhythm echo: --header Authorization: env:RHYTHM_ECHO_STAGING_AUTH is not set`
  - `rhythm echo: --header X: @big.txt is more than 64 KiB`; `rhythm echo: --header X: @token.txt doesn't exist`
  - `rhythm echo: --header: want "Name: value", e.g. -H "Authorization: env:RHYTHM_ECHO_STAGING_AUTH"`
  - `rhythm echo: --header X: has a line break`
  - `rhythm echo: --cookie: want name=value, e.g. --cookie "session=env:RHYTHM_ECHO_SESSION"`; `rhythm echo: --cookie session: the value has a ; or a line break; give one cookie per --cookie`
  - (all exit 2)
- A plain value prints PRD 10.2 message 22 on stderr once per command: `rhythm echo: --header value on the command line shows in ps to every user on this machine; use @file or env:NAME`; for cookies `rhythm echo: --cookie value on the command line shows in ps to every user on this machine; use @file or env:NAME`.
- `consent: headers` values `${env:RHYTHM_ECHO_NAME}` are read from the environment: unset is `rhythm echo: consent: headers: Authorization: RHYTHM_ECHO_STAGING_AUTH is not set` (exit 2).
- `--send-hits` on a host under `production:` (the host or a subdomain, as Echo's actions match) is message 6 before any browser starts or any folder is made: `rhythm echo: --send-hits on www.shop.example.com, which matches "shop.example.com" under production:. Echo holds tracker hits on production so your analytics stay clean; leave --send-hits off` (exit 2).
- `--show-ids` with `--md`, `--junit`, `-o *.md` or `-o *.xml`: `rhythm echo: --show-ids keeps tracking IDs unmasked; it can't be used with Markdown or JUnit output, which are meant to be shared` (exit 2).
- `-k` on a public site without `--insecure-public`: `rhythm echo: -k on https://shop.example/, a public site: evidence from an unverified connection proves little; add --insecure-public if you mean it` (exit 2). Private: loopback, private and link-local addresses; `localhost`; one-label names; names under `.localhost .test .local .internal .lan .home.arpa .localdomain .intranet .corp .private`; and hosts `--map-host` answers from such an address. No DNS lookup is made to decide.
- `--show-browser` sets `--parallel 1`.
- The store: `--store`, else the config's folder, else `./.echo`. Nothing is created until the check starts.
- `checks:` levels of `consent/` IDs go to the verdict (`off` removes a check). `consent: ignore` entries go to the verdict as written.
- `consent: trackers` go to the tracker catalog's `AddCustom` once per command; its error is `rhythm echo: consent: trackers: <the catalog's message>` (exit 2).
- `--map-host host=addr` (repeatable, on top of `consent: map_hosts`, the flag winning for the same host): `rhythm echo: --map-host "x": want host=address, e.g. *.shop.test=127.0.0.1:18950` (exit 2). The address is host:port or an http:// or https:// URL.
- `--echo` asks Echo at `--echo=<url>`, else `RHYTHM_ECHO_URL`, else `http://127.0.0.1:8025`, with `RHYTHM_ECHO_TOKEN`.
- `--sites <file>`: Soundcheck fleet's file, a list or a mapping with `sites:`. Per entry Echo reads `name`, `url` and `consent: {urls, args}`; Soundcheck's `config`, `env_prefix` and `args` are accepted and left alone. A site's pages default to its `url`; `consent: urls` paths are read against it. Errors (exit 2, `rhythm echo: sites.yaml: ...`):
  - `no sites listed`; `line 1: "sitez" isn't a key; did you mean sites?`; `line 1: a site: "envprefix" isn't a key; did you mean env_prefix?`; `line 1: consent: "url" isn't a key; did you mean urls?`
  - Soundcheck's name rules: `site "../acme": name must be letters, digits, dots, dashes and underscores (up to 64), starting with a letter or digit`; `site "Acme": the name is already used by site "acme"` (compared without case); `site "acme": url is missing`; `site "acme": url "ftp://a.test": want an http or https URL`.
  - A site's `consent.args` may set only `--runs --pages --settle --banner-wait --timeout --retries --cmp --accept-selector --reject-selector --click --consent-mode --exempt --geo --locale --timezone --viewport --follow-host -A -H --cookie`; anything else: `site "a": consent: args can't set --send-hits; only the command line can`. `-H` and `--cookie` values there must be `env:RHYTHM_ECHO_NAME`: `site "a": consent: args: header and cookie values must be env:RHYTHM_ECHO_NAME, never a file or the value itself`. A page in args: `site "a": consent: args take flags only, not "/menu/"; list pages under consent: urls`. The file is shared, so nothing in it can read files, run programs, send hits, unmask IDs, turn off TLS checks or move results.
  - A sites file over 4 MiB: `--sites sites.yaml: the file is more than 4 MiB`.
- More than 50 pages in one check: `rhythm echo: 63 pages is more than 50 for one check; split the sites file` (exit 2).

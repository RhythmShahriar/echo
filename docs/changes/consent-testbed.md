# Consent testbed: changes

Every user-visible change of the consent testbed (commands, flags, output
lines, messages), with the exact text.

## X1 Fixture server

- New command `go run ./testbed/consent/server/cmd/consent-testbed` with flags `-root` (default `testbed/consent`, or `.` inside it), `-listen` (default `127.0.0.1:23400`), `-admin` (default `127.0.0.1:23401`), `-tls`, `-ca` (default `<root>/ca`), `-make-ca <dir>`, `-print-map`, `-echo-proxy`, `-echo-ca`.
- `-tls` serves https beside plain http on the same `-listen` port: each connection is told apart by its first byte, because Chrome's host resolver rules and Echo's `--map-host` send every name and port to one address.
- Start lines: `consent-testbed: sites and tags on 127.0.0.1:23400 (http and https), admin and sink on 127.0.0.1:23401` (`(http)` without `-tls`) and `consent-testbed: map with <the -print-map line>`.
- `-print-map` prints one line: `--map-host '*.shop.test=127.0.0.1:23400' --map-host analytics.tiktok.com=127.0.0.1:23400 ... --map-only` (every stand-in host, sorted).
- `-make-ca <dir>` prints `consent-testbed: wrote the testbed CA to <dir>`; on an existing CA it fails with `consent-testbed: <dir>/ca.pem exists; delete the folder to make a new CA`. The CA is name-constrained to `.test`, `localhost` and the stand-in hosts.
- `-tls` without a CA: `consent-testbed: testbed CA: open <dir>/ca.pem: no such file or directory (make ca creates it)`.
- A root without `sites/`: `consent testbed: no sites folder in <root> (pass -root testbed/consent)`.
- `-echo-proxy` must be `http://` on a loopback address or `localhost`: `-echo-proxy "<value>": want http://host:port of rhythm-echo up` and, in Go mode, `-echo-proxy "<value>": want a loopback address (Compose service names need Docker mode)`. A one-label Compose name such as `echo` is accepted only in Docker mode, when `-internal` names a service (`-internal shop:8081`); there a refusal reads `-echo-proxy "<value>": want a loopback address or a Compose service name`.
- A host the server doesn't serve answers `421` with `not a consent testbed host: <host>` and is counted under `unmapped`.
- `/logout/` and `/cart/` on any scenario answer `This page must never be opened by a scan.` and are counted under `forbidden`.
- Admin endpoints (admin port only): `GET /_admin/health` (`ok`), `GET /_admin/state?id=c01[&state=good|broken]` (`{"id": "c01", "state": "broken"}`; unknown id 404 `no scenario "x"`; bad state 400 `state: want good or broken`), `GET /_admin/sites`, `GET /_sink/count[?scenario=c01]` (`{"hits", "by", "forbidden", "internal", "unmapped"}`), `GET /_sink/hits?scenario=c01`, `POST /_sink/reset` (204), `/_internal/*` (the ssrf-probe target, counted under `internal`).
- `testbed/consent/toggle.sh <id|all> good|broken` prints `c01 -> broken`; `toggle.sh status` prints `all scenarios good` or `broken: c01 c02`; an unknown id fails with `./toggle.sh: unknown scenario x (see sites/)`.
- `make -C testbed/consent ca`, `serve`, `map` and `toggle ID=c01 STATE=broken`.

## X5 Harness and benchmark

- `go run -tags testbed ./testbed/consent/bench` (the package now builds without the tag too, so its tests run with every `go test ./...`). Flags: `-bin` (default `bin/rhythm-echo`), `-mode go|docker` (default `go`), `-rounds` (10), `-jobs` (2, scenarios checked at once), `-only c01,g01,e05` (scenarios, Docker variants and probes), `-skip control,probes,detect,fleet,tools`, `-out` (default `docs/benchmark-consent.md`), `-work` (default `testbed/consent/bench/work`, emptied at start), `-root`, `-timeout` (5m per command), `-listen` (Go mode, `127.0.0.1:23400`), `-probe-port` (23410), `-diff a.json b.json`.
- Per scenario: `rhythm-echo consent https://<id>.shop.test/ --json -o result.json --fail-on none <scenario args> [--runs ...]` plus, in Go mode, the `-print-map` flags; a comparison scenario's good state drops `--against <name>` and adds `--save <name>`; both of its states add `--store ../.echo` so the broken state finds that baseline; `{echo}` becomes the Echo the harness starts (Go mode: `rhythm-echo up --seal --listen 127.0.0.1:23438 --smtp off --proxy 127.0.0.1:23439`; Docker mode: `http://echo:8025`).
- Outcomes in results.json and the scoreboard: `caught`, `missed`, `did not load`, `clean`, `false alarm`, `failed`, `not run`. Details: `no <expect> | ...; found: <check>: <title>; ...` (the actual titles next to the expected substring), `caught for the wrong reason: <forbid>; found: ...`, `no JSON report (exit <n>): <stderr tail>`, `<n> tracker hits reached the sink in held mode: <host/path> <n>, ...`, `the run opened /logout/ or /cart/ <n> times`, `not in the run's scripts: gtag, fbevents`, `inconclusive: <run> <reason>, ...`, `good state <outcome>: <detail>` (a catch whose good state isn't clean doesn't count).
- Stand-ins checked against the run's `scripts[]` (and script hits): `gtag`, `gtm`, `fbevents`, `tiktok`, `linkedin`, `uet`, `clarity`, `hotjar`, `plausible`, read from the rendered page in its current state.
- Control pass: every good state `-rounds` times; flakes are rounds whose verdict and issue keys differ from round 1 (`round <n> differs from round 1: <sig>, then <sig>`).
- Measures (PRD 18.2 and 19), each `met`, `missed` or `not measured`: catches, false alarms, flakes, click success per CMP (good states only), leaked hits, e10 completeness, time per page p50 and p95 (from `duration_ms` per page), `consent detect` slowest (wall time on every good state with a CMP), fleet (a generated 50-site `sites.yaml`, the good states plus `<id>-repeat-<n>` entries, `--parallel 6`), peak resident memory of rhythm-echo itself with Chrome left out (its own high water mark, `VmHWM` in `/proc/<pid>/status`, polled every 20 ms: by the bench in Go mode and by `peakmem` inside the runner in Docker mode; Linux only, `not measured` elsewhere; a child's rusage is not used because it counts the largest process the child reaped, which is Chrome), binary size growth against `bench/size-v1.1.2.txt` (16519328 bytes: v1.1.2 rebuilt from its tag with the release flags; judged only in Docker mode on `runtime/rhythm-echo`) and `make reproduce` (noted, run separately).
- Exit codes: 0; 1 with `bench: targets missed:` and one line per miss (Go mode: scenario misses and failures, false alarms, flakes, leaks, probes; Docker mode: also every missed measure and, on a full run, every measure not measured, printed as `<measure>: not measured (<note>), target <target>`, except the `make reproduce` row, which `-diff` judges); 2 usage (`bench: -mode "x": want go or docker`, `bench: -skip "x": want control, probes, detect, fleet, tools`, `bench: -diff takes two files: -diff a.json b.json`); 3 when the benchmark couldn't run (`bench: -only zz9: no scenario, variant or probe by that id`, `bench: -bin <path>: ... (make build)`, `bench: the testbed's sites on 127.0.0.1:23400: ... - Progress on stderr: `bench: <id> <outcome> <detail>`, `bench: control <id>: <n> rounds, <n> false alarms, <n> failed, <n> flakes`, `bench: no Echo for --echo, so c18 fails: <error>`.
- `-diff` prints `<id>: <outcome a> | <outcome b>` per difference (scenarios as `echo <o>, good state <o>, <tool> <o>`, `control <id>` as counts, probes) or `<n> outcomes, the same in both runs`; exit 1 on any difference; `<file>: no outcomes; was the run aborted?` (exit 3).

Without a JSON report it reads completeness from the newest `consent.json` (the CLI's `Interrupted before every run finished: this result is incomplete.` note).
- e18 makes its token, header and cookie values at run time (`tbtok_<hex>`); the header and cookie go through `-H "Authorization: env:RHYTHM_ECHO_TB_AUTH"` and `--cookie env:RHYTHM_ECHO_TB_COOKIE`.
